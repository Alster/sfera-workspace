# AGENTS.md — робоча тека для спільної роботи над SFERA і симулятором

Ця тека — точка входу для AI-агентів (Claude Code, Codex тощо) і людей, коли задача зачіпає **обидва** проєкти
або їхню взаємодію. Сама вона коду продуктів не містить: тут лише документація про зв'язок проєктів
і спільні інструменти. Код лежить у сусідніх репозиторіях.

## Структура

```
../sfera/               SFERA — операторська станція (git: Alster/sfera-sfera)
../sfera-target-sim/    симулятор дронів і цілей для SFERA (git: Alster/sfera-target-sim)
sfera-workspace/        ця тека: AGENTS.md, docs/, tools/ (власний git — за рішенням людини)
  docs/integration.md   контракт SFERA ↔ симулятор, порти, відомі розбіжності
  tools/joint_check.py  спільна жива перевірка без GUI
```

Шляхи в документації цієї теки — відносно `sfera-workspace/`.

## Мета

SFERA — засіб супроводу та відео-зйомки літальних апаратів літакового типу. Оператор наводить дрони-камери
на повітряну ціль, а автопілот SFERA веде їх на перехоплення і супровід. Симулятор існує, щоб відпрацьовувати це
без заліза і без ризику. Звідси пріоритети:

- **надійність і передбачуваність важливіші за нові функції** — хибна команда дрону небезпечна для людей на землі;
- ціль — швидкий об'єкт, дані про неї неточні й приходять із затримкою: зміни в перехопленні оцінюйте саме на такому сценарії;
- поведінку, перевірену лише в симуляторі, не видавайте за готову до реального застосування.

## Проєкти

**SFERA** (`../sfera`) — Python + `pywebview`, керує 1–2 дронами ArduPilot по MAVLink: телеметрія, карта/радар,
автопілот перехоплення й супроводу цілі на боці SFERA, RTH/LAND, журнали і програвач сеансів. Надсилає **реальні
команди польоту** — зміни в керуванні вважайте safety-critical. Є golden-тести (`unittest`) і SITL-стенд.

**sfera-target-sim** (`../sfera-target-sim`) — Tkinter-застосунок для тестування SFERA без заліза: віртуальні дрони
(MAVLink, прикидаються ArduCopter; TCP `tcpin` або COM) і летючі цілі (UDP CSV ~10 Гц). Проста кінематична
модель, не SITL. Юніт-тестів немає, є `tools/smoke_test.py`.

Як вони поєднуються — [docs/integration.md](docs/integration.md).

## Правила

- **Кожен репозиторій має власний `AGENTS.md` — прочитайте його перед зміною в ньому.** Його правила (інваріанти,
  перевірки, що не комітити) мають пріоритет над цим файлом.
- **Мова:** документація, коміти й відповіді — українською. Жодного російського тексту. Перевірка змінених файлів:
  `grep -nP "[\x{044B}\x{044D}\x{044A}\x{0451}\x{042B}\x{042D}\x{042A}\x{0401}]" <файли>` має бути порожнім.
- **Коміти — окремо в кожному репозиторії** (`git -C ../sfera ...`), лише конкретні файли (`git add <файли>`, не `-A`).
  Не пуште і не комітьте без прохання. Зміна, що зачіпає обидва боки, — два коміти, які посилаються один на одний за змістом.
- **Контракт між проєктами** (формат UDP, набір MAVLink-повідомлень, порти) змінюйте лише свідомо і з обох боків
  одночасно; оновлюйте [docs/integration.md](docs/integration.md) і документацію обох репозиторіїв.
- Не заявляйте, що поведінку польоту «перевірено», якщо проходили лише тести чи симулятор: симулятор — спрощена
  модель, не ArduPilot.

## Перевірка

```bash
# SFERA: golden- і юніт-тести (≈5 с)
(cd ../sfera && .venv/bin/python -m unittest discover -s tests -t .)
# симулятор: смок-тест без GUI (порти 15760/tcp, 15551/udp)
(cd ../sfera-target-sim && .venv/bin/python tools/smoke_test.py)
# разом: симулятор + SFERA без GUI — підключення, зліт, перехоплення, LAND (≈30 с; порти 15790/tcp, 15591/udp)
../sfera/.venv/bin/python tools/joint_check.py
```

- Змінили щось на межі проєктів (MAVLink, UDP, порти, висоти) — проганяйте всі три.
- `joint_check.py` запускається у venv SFERA і імпортує модулі симулятора без Tk. SFERA пише журнали в `../sfera/LOG/`
  (у `.gitignore`), власний stdout — у `/tmp/sfera_joint_*.log`.
- GUI обох застосунків у середовищі агента зазвичай не запускається (немає дисплея).

## Підводні камені

- `HeadlessSfera` (`../sfera/tools/sitl/headless.py`) підміняє `sys.stdout` своїм журналом: у власних скриптах
  друкуйте в збережений заздалегідь `sys.stdout` або в `stderr`. Задавайте `stdout_log` абсолютним шляхом поза репозиторієм.
- GUI симулятора перезаписує `../sfera-target-sim/simulator_config.json` — перевіряйте `git diff` перед комітом.
- У SFERA після `start_link` HOME може прийти раніше за розібраний HEARTBEAT: чекайте на `mode`/`gps_fix`, а не лише на `connected`.
